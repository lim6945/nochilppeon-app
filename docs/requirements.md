# 📘 [기획 명세서] 놓칠뻔 — 나에게 맞는 지원정책 추천

## 1. 서비스 개요
- **서비스명:** 놓칠뻔
- **개요:** 정부·지자체의 지원정책은 5,000개가 넘을 정도로 다양하지만(청년, 신혼부부, 소상공인, 어르신, 한부모가정 등 대상별로 흩어져 있음), 본인에게 맞는 정책을 찾기가 번거롭습니다. 사용자가 나이·거주지역·가구 상황(1인가구/신혼부부/자녀유무 등)·재직상태·소득구간 등 간단한 정보만 입력하면, 조건에 맞는 정책만 필터링해서 추천하고 공식 신청 페이지로 바로 연결해주는 웹 애플리케이션입니다. 특정 연령대(청년)에 한정하지 않고 다양한 생애주기를 아우릅니다.

## 2. 문제 정의 & 근거
정부 지원정책은 다양하게 존재하지만, 신청 절차가 몰라서/복잡해서 대상자인데도 혜택을 놓치는 국민이 상당수 존재한다.
- 지난해 근로장려금 신청 대상 중 22만 가구가 신청하지 않아 지원받지 못했고, 이들이 모두 신청했다면 받을 수 있었던 금액은 최대 2,098억원으로 추산된다. 최근 5년간 미신청 가구는 141만 7,000가구, 미신청 추산액은 5년간 최대 1조 2,846억원(연평균 2,569억원)에 달한다. (경향신문, 2023, 국세청 자료 기준)
- 국세청 설문조사 결과 미신청자의 34.2%는 안내문 자체를 받지 못했고, 안내문을 받은 신청자의 34.9%는 신청 방법을 몰라서 신청하지 못했다고 응답했다.
- 우리나라 복지 사업은 중앙부처 약 400개, 지방자치단체 약 4,600개로 총 5,000개에 달해 종류가 너무 많아 본인이 받을 수 있는 혜택을 놓치는 국민이 적지 않다. (뉴스핌, 2026)

## 3. 기존 서비스 대비 차별화 포인트 (브로셔 "제작 회고"에 반영)
- **보조금24(정부 공식 앱)**, **복지로(정부 포털)**와 핵심 매칭 메커니즘은 유사함을 인지하고 있음
- 차별점 1: 방대한 전체 정책을 다 보여주는 게 아니라, 생애주기 전환점(자취 시작, 결혼, 창업 등)에 꼭 필요한 정책만 소수로 큐레이션해서 "선택 피로"를 줄임
- 차별점 2(향후 계획): 교통법규·과태료 등 사용자 관련 규정이 바뀌면 푸시 알림으로 먼저 안내하는 기능 — 기존 두 서비스 모두 이 기능은 없음

## 4. 핵심 기능 및 화면 요구사항

### 톤앤매너 (전체 카피 가이드)
서비스 전체 문구는 딱딱한 격식체가 아니라 친구가 말해주는 듯한 캐주얼하고 코믹한 톤으로 작성합니다. 아래 표현을 실제 화면 문구로 그대로 사용해주세요.

| 위치 | 문구 |
|---|---|
| 로고 옆 아이콘 | 경고 아이콘이 아니라 윙크하는 표정 아이콘 (Tabler `mood-wink` 아이콘 사용, 색상은 앰버 계열) |
| 메인 서브 카피 | "어? 이거 나 놓칠 뻔했잖아?!" |
| 입력 화면 제출 버튼 | "내 돈 어디 숨었나 찾아보기" |
| 결과 화면 타이틀 | "짜잔! 하마터면 놓칠 뻔한 것들" |
| 결과 없을 때 안내 | "음... 지금은 딱히 없네요. 다음에 또 놓칠 뻔한 거 생기면 알려드릴게요" |
| 하단 소셜프루프 | "지금까지 N명이 하마터면 놓칠 뻔한 걸 잡았어요" (N은 실시간 누적 이용자 수) |

### 정책 카테고리 (9종, 고정)
결과를 분류하는 카테고리는 아래 9개로 고정합니다. 정책 데이터(API 응답 또는 fallback 데이터)의 각 항목은 반드시 이 9개 중 하나로 분류되어야 합니다. 신혼부부/임신·출산·육아/어르신을 각각 별도 카테고리로 분리하고, 기존에 빠져 있던 교육(장학금·학자금)을 추가했습니다.
1. 주거
2. 금융·자산형성
3. 취업
4. 창업
5. 신혼부부·결혼
6. 임신·출산·육아
7. 어르신·노후
8. 교육
9. 생활·복지 (위 8개에 속하지 않는 나머지 전부: 의료비, 에너지바우처, 문화누리카드 등)

### 화면 1 — 정보 입력 화면 (Input, 별도 라우트 `/`)
- 로고(윙크 아이콘 + "놓칠뻔") + 서브카피 "어? 이거 나 놓칠 뻔했잖아?!"
- 입력 항목:
  - **나이**: 19세 ~ 100세 (드롭다운 또는 숫자 입력)
  - **거주 지역** (17개 시도 드롭다운): 서울특별시, 부산광역시, 대구광역시, 인천광역시, 광주광역시, 대전광역시, 울산광역시, 세종특별자치시, 경기도, 강원특별자치도, 충청북도, 충청남도, 전북특별자치도, 전라남도, 경상북도, 경상남도, 제주특별자치도
  - **현재 상태** (드롭다운): 재직중 / 구직중 / 대학생 / 프리랜서 / 자영업 / 은퇴 / 무직·기타
  - **가구 상황** (다중 선택 가능한 드롭다운 — 거주지역 드롭다운과 같은 UI 패턴이되, 체크박스로 여러 개 선택 가능하고 선택된 개수를 "2개 선택됨" 형태로 표시): 1인가구 / 신혼부부·예비부부 / 자녀있음 / 다자녀가구 / 한부모·조손가구 / 다문화가정 / 북한이탈주민 / 장애인가구 / 보훈대상자 / 저소득층 / 무주택가구 / 해당없음
  - **한 달에 대충 얼마 벌어? (몰라도 괜찮아요 &gt;,&lt;)** — "중위소득 %" 같은 전문용어 대신 아래처럼 직관적인 금액 구간으로 표시:
    - 200만원 이하
    - 200~300만원
    - 300~400만원
    - 400만원 이상
    - 음... 잘 모르겠음 (선택 시 소득 조건 필터를 건너뛰고, 결과 화면에서 "이 정책들은 소득 기준이 있으니 신청 전 확인하세요" 안내 문구를 표시)
- **[내 정보 저장하기] 체크박스** (기본값: 체크됨), 라벨: "내 정보 저장하기 — 다음엔 또 안 물어볼게요"
  - 체크된 상태로 제출 → localStorage에 저장, 다음 방문 시 자동으로 입력값 채워짐
  - 체크 해제 상태로 제출 → 저장하지 않고 이번 결과 조회에만 사용 (새로고침하면 다시 처음부터 입력)
- [내 돈 어디 숨었나 찾아보기] 버튼
- **재방문 시**: localStorage에 저장된 정보가 있으면 각 입력 필드에 자동으로 채워진 상태로 시작 (사용자가 원하면 바로 수정 가능)

### 화면 2 — 결과 화면 (Result, 별도 라우트 `/result`)
- 상단 헤더: 좌측에 로고, 우측에 **"내 정보" 요약 칩** (예: "25세·서울·재직중" + 연필 아이콘) — 클릭하면 화면 1(입력 화면)로 이동하며 기존 입력값이 채워진 채로 수정 가능
- 내 정보 칩 옆에 **[삭제] 아이콘 버튼** (휴지통 아이콘) 배치 — 클릭 시 localStorage에 저장된 정보를 완전히 삭제하고, 다음 방문 시 처음부터 다시 입력하도록 함 (삭제 전 "저장된 정보를 지울까요?" 확인 문구 표시)
- 결과 타이틀 "짜잔! 하마터면 놓칠 뻔한 것들" 바로 아래에 **"총 N개를 찾았어요!" 문구**로 전체 매칭 개수 표시
- **카테고리 필터 pill**: "전체" + 9개 카테고리를 가로로 나열한 선택형 버튼. 각 pill에는 카테고리명과 결과 개수를 함께 표시 (예: "전체 3", "주거 1", "금융 1"). 결과 0개인 카테고리 pill은 숨기거나 비활성화 처리. 특정 카테고리를 누르면 해당 카테고리 결과만 필터링해서 보여줌 (기본값은 "전체")
- "전체" 선택 시에는 카테고리별로 섹션을 나누어 표시합니다. 각 섹션은 카테고리명 + 아이콘 + 해당 카테고리 결과 개수(예: "주거 (1)")를 헤더로 하고, 그 아래 정책 카드들을 나열합니다. 결과가 없는 카테고리는 섹션 자체를 표시하지 않습니다.
- 각 정책 카드: 정책명, 한 줄 설명(지원 내용 요약), [신청 바로가기] 버튼(공식 신청 페이지로 외부 링크 연결). 조건 판단이 애매한 정책은 카드 우측 상단에 작은 **"조건 확인 필요" 배지**(주황색)를 표시
- 정책이 하나도 안 맞으면 "음... 지금은 딱히 없네요. 다음에 또 놓칠 뻔한 거 생기면 알려드릴게요" 안내
- 하단에 Supabase DB와 연동된 실시간 **"지금까지 N명이 하마터면 놓칠 뻔한 걸 잡았어요"** 문구 표시

## 5. 정책 데이터 연동 (보조금24 오픈API 실시간 연동)
정책 데이터는 정적 JSON이 아니라 행정안전부의 "대한민국 공공서비스(혜택) 정보" 오픈API를 실시간으로 호출해서 가져옵니다.

### API 기본 정보 (확인 완료)
- Base URL: `https://api.odcloud.kr/api`
- 목록 조회: `GET /gov24/v3/serviceList` (파라미터: `page`, `perPage`, `serviceKey`)
- 상세 조회: `GET /gov24/v3/serviceDetail` (서비스ID로 상세정보 조회)
- 인증: 쿼리 파라미터 `serviceKey`에 인증키(디코딩 키) 그대로 붙이는 방식
- 인증키와 실제 응답 예시는 `docs/subsidy24-api-info.md`에 기재되어 있습니다.

### 실제 응답 필드 (serviceList 기준, 확인 완료)
`서비스ID`, `서비스명`, `서비스목적요약`, `서비스분야`(자체 분류 필드), `지원대상`, `지원내용`, `선정기준`, `소관기관명`, `소관기관유형`, `신청기한`, `신청방법`, `전화문의`, `상세조회URL`, `조회수` 등. 코드값이 아니라 사람이 읽을 수 있는 한글 텍스트로 제공됩니다.

### 카테고리 매핑 전략 (2단계)
API 자체에 `서비스분야`라는 분류 필드가 있지만(예: "보육·교육", "주거·자립", "농림축산어업", "행정·안전" 등), 우리 서비스의 9개 고정 카테고리와 정확히 1:1로 대응하지 않으므로 아래 2단계로 매핑합니다.

**1단계 — `서비스분야` 값으로 1차 분류 (기본값 부여):**
- "주거·자립" → 기본값 "주거"
- "보육·교육" → 기본값 "교육" (단, 2단계에서 영유아/보육 키워드 있으면 "임신·출산·육아"로 재분류)
- "고용·창업" → 기본값 "취업" (단, 2단계에서 "창업" 키워드 있으면 "창업"으로 재분류)
- "임신·출산" → "임신·출산·육아"
- "신체건강", "정신건강", "문화·환경", "행정·안전", "농림축산어업", "서민금융" 등 그 외 전부 → 기본값 "생활·복지"
- 위 목록에 없는 새로운 `서비스분야` 값이 나오면 우선 "생활·복지"로 분류

**2단계 — `서비스명` + `지원대상` 텍스트 키워드로 세분화 (1단계 분류를 덮어씀):**
- "신혼부부", "혼인", "예비부부" 키워드 포함 → "신혼부부·결혼"
- "임신", "출산", "영유아", "보육", "어린이집" 키워드 포함 → "임신·출산·육아"
- "노인", "어르신", "기초연금", "노후" 키워드 포함 → "어르신·노후"
- "창업", "소상공인" 키워드 포함 → "창업"
- "장학", "학자금", "등록금" 키워드 포함 → "교육"
- "저축", "적금", "대출", "장려금" 키워드 포함 → "금융·자산형성"
- 위 키워드에 하나도 해당하지 않으면 1단계 결과를 그대로 사용

사용자가 입력한 나이/지역/가구상황/재직상태/소득구간 조건은 `지원대상`, `선정기준` 텍스트에 포함된 나이·소득 조건과 최대한 매칭해서 필터링합니다. 텍스트 파싱이 완벽하지 않을 수 있으므로, 조건이 애매하면 일단 결과에 포함시키고 카드에 "조건 확인 필요"로 표시하는 것을 기본 정책으로 합니다.

- **중요(안정성 대책)**: 부스 시연 중 공공 API가 응답하지 않거나 느릴 수 있으므로, API 호출이 3초 이상 걸리거나 실패하면 미리 준비한 대체(fallback) 정책 데이터 12~15개(아래 예시 참고)를 정적 JSON으로 대신 보여주세요. 사용자 입장에서는 어느 쪽이든 자연스럽게 결과가 나와야 합니다.

## 6. 백엔드 연동 로직
- 사용자 입력 정보(나이/지역/재직상태/소득구간): 서버로 전송하지 않고 브라우저 **localStorage**에 저장. 재방문 시 자동으로 불러와서 입력 화면에 채워주고, 결과 화면의 "내 정보" 칩에도 표시.
- 정책 데이터: 5번 항목대로 보조금24 API 실시간 호출 + 실패 시 fallback 정적 JSON
- **누적 이용자 수 카운트**: 사용자가 [내 돈 어디 숨었나 찾아보기] 버튼을 눌러 결과를 조회할 때마다 Supabase의 `usage_counter` 테이블 값을 1 증가시키고, 결과 화면에서 누적 합계를 실시간으로 렌더링. 개인정보나 입력값은 Supabase에 절대 저장하지 않고 순수 카운트만 저장.
