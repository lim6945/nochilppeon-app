## API 기본 정보 (확인 완료)

* **Base URL**: `https://api.odcloud.kr/api`
* **목록 조회 엔드포인트**: `GET /gov24/v3/serviceList`
* **상세 조회 엔드포인트**: `GET /gov24/v3/serviceDetail`
* **인증 방식**: 쿼리 파라미터 `serviceKey`에 인증키를 그대로 붙임 (Swagger에서는 "ApiKeyAuth2" 방식)
* **파라미터**: `page`(페이지 번호, 기본 1), `perPage`(페이지당 개수, 기본 10), `serviceKey`(인증키)
* **비용**: 무료, 개발계정 트래픽 1일 10,000건

## 요청 URL 예시 (실제 확인됨)

```
https://api.odcloud.kr/api/gov24/v3/serviceList?page=1\&perPage=10\&serviceKey=본인의\_서비스키
```

## 참고

* `serviceList`는 목록만 간략히 주고, 더 자세한 내용이 필요하면 `서비스ID`로 `serviceDetail`을 추가 호출하면 됩니다. (다만 위 응답에도 지원대상/지원내용/선정기준이 텍스트로 포함되어 있어서, MVP 단계에서는 `serviceList` 응답만으로도 카드 표시와 필터링에 충분합니다.)
* `supportConditions` 엔드포인트는 `24B01` 같은 코드로만 응답이 나오고 공개된 코드 정의 문서를 찾지 못해서, 이번 프로젝트에서는 사용하지 않습니다. 대신 `serviceList`의 한글 텍스트 필드(서비스분야/지원대상/서비스명)로 카테고리 매핑과 조건 필터링을 진행합니다. (자세한 매핑 로직은 `docs/requirements.md` 5번 항목 참고)
